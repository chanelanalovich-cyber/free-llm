**Дата:** 2026-11-11

## 2. Что реализовано

12 файлов, ~700 строк, зависимостей ровно три (`next@16.4.6`, `react@19.3.1`, `react-dom@19.3.1`).

| Файл | Роль |
|---|---|
| `app/api/chat/route.ts` | Серверный POST: валидация `message` (trim, не пусто, ≤ 4000 → 400/413), вызов `${LLM_BASE_URL}/chat/completions` с `stream: true`, проброс тела как `text/event-stream`. Ключ только на сервере. `request.signal` прокинут в upstream, чтобы «Стоп»/закрытие вкладки обрывали запрос. Заголовки против буферизации: `Cache-Control: no-cache, no-transform`, `X-Accel-Buffering: no`. |
| `components/chat.tsx` | Клиент: `fetch` + `response.body.getReader()`, разбор SSE по пустой строке с сохранением неполного хвоста в буфере, `choices[0].delta.content` дописывается в состояние, `delta.reasoning` — в свёрнутый блок. Enter / Shift+Enter (с учётом IME), счётчик 4000, `AbortController` для «Стоп», автоскролл, `aria-live`. Типизация без `any`: `parseChunk(raw: unknown)`. |
| `app/page.tsx` | Серверный компонент с `dynamic = "force-dynamic"`, передаёт `LLM_MODEL` в UI как подпись (env читается на каждый запрос, а не на билде). |
| `app/layout.tsx`, `app/globals.css` | Тёмная тема, метаданные, стили (карточка, composer, печатающийся курсор, ошибки). |
| `next.config.ts` | `compress: false` — намеренно: gzip-буферизация ломает посимвольную отдачу. |
| `.env.example` | 4 пресета: OpenRouter free (по умолчанию), DeepSeek, локальный OmniRoute, Qwen/DashScope. |
| `README.md` | Запуск, таблица провайдеров и цен, устройство стриминга, границы демо. |
| `.gitignore`, `package.json`, `tsconfig.json` | Служебное; скрипты `dev`/`build`/`start`/`typecheck`. |

Обрыв предыдущей сессии, судя по состоянию, произошёл уже **после** написания кода: README
описывает итоговую архитектуру и решения, включая неочевидное `compress: false` и обработку
`delta.reasoning`. Незаконченных заготовок, TODO и мёртвых файлов нет.

## 3. Чем проверено

```bash
cd a_projects/llm-stream-demo
npm run typecheck    # tsc --noEmit → exit 0
npm run build        # Next 16.4.6 (Turbopack) → compiled, 4 static pages, ƒ /api/chat
```

End-to-end стриминг без реального ключа: поднята локальная заглушка OpenAI-совместимого
провайдера (`/v1/chat/completions`, отдаёт по токену каждые 250 мс), `next start -p 3123` запущен
с `LLM_BASE_URL=http://127.0.0.1:20131/v1`.

| Проверка | Результат |
|---|---|
| Заглушка получила `model=stub-model`, `stream=true`, `message=привет` | ✅ контракт запроса верный |
| `POST /api/chat` | ✅ `200`, `text/event-stream` |
| Приход чанков | ✅ `+322 / +553 / +803 / +1053 / +1304 / +1557` мс |
| Буферизация | ✅ нет: интервалы совпадают с темпом заглушки (250 мс), а не слипаются в конце |
| Пустой `message` | ✅ `400` + понятный текст |
| `message` 4001 символ | ✅ `413` + текст про лимит |
| Битый JSON | ✅ `400` + текст про формат |
| `GET /` | ✅ `200`, HTML рендерится |
| Подпись модели после фикса | ✅ `next start` с `LLM_MODEL=model-at-runtime` → в HTML `model-at-runtime` (маршрут `ƒ /`) |

Вывод: серверный пайплайн (валидация → провайдер → SSE → клиент) собран правильно, поток
доходит по мере генерации, ограничение по длине и коды ошибок работают.

## 4. Что НЕ проверено (и почему)

- **Реальный провайдер.** Нет `.env.local` и ключа; env-файлы по правилам агента не создаются и
  не изменяются пользователем-агентом. Проверен только контракт запроса на заглушке.
- **UI в браузере** — печать текста, блок размышлений, «Стоп», автоскролл. Логика разбора SSE
  и `AbortController` проверены чтением кода, но не кликом.
- **Ветка ошибок провайдера** (502/499) и «Провайдер не настроен» (500) — только чтением кода.
- **Тестов нет** — осознанное решение демо (README, раздел «Ограничения демо»), не регресс.
